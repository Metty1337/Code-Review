# Review на реализацию от [@aveasura](https://github.com/aveasura) проекта [Обмен валют](https://zhukovsd.github.io/java-backend-learning-course/projects/currency-exchange/)

[Сама реализация](https://github.com/aveasura/currency-exchange)

## Реализация

Смотрел по деплою, бот сообщества ругается на порт, поэтому дергал вручную API.

- Хорошо:
    - Свой фронт, опыт верстки не будет лишним.
    - Валидация на длину параметров валюты.
    - На глаз - ответы API соответствуют ТЗ.

## По коду

### package model

- Используешь `Long` для `id` - супер
- `BigDecimal` для `rate` - идеально.
- `record` для моделей в целом приемлемый архитектурный выбор.

### package repository

- `Optional` используется для поиска курса, в то же время метод поиска валюты выбрасывает исключение при ненаходе
  вылюты. Имхо я бы придерживался единообразия.
- Выделены интерфейсы для репозиториев - хорошо.
- `Optional<ExchangeRate> findByBaseCurrencyIdAndTargetCurrencyId` - упростил бы название до `findById`.
- Нарушение I из SOLID - метод
  `protected <T> List<T> executeList(String sql, PreparedStatementSetter statementSetter, RowMapper<T> rowMapper)` -
  используется только в одном наследнике, а другому он не нужен.

### package service

- Я не до конца понял смысл команд, их обычно используют для четкого разделения доменного слоя от инфраструктуры, но в
  обычном CRUD мне кажется это overhead. Тем более команды используются только для курсов, но не для валют - нет того-же
  CreateCurrencyCommand. Мне кажется стоит упростить и убрать команды.
- Интерфейсы `CreateService` и `GetAllService` я бы переименовал в что-то более Java-подобное.
- Выделены интерфейсы - хорошо.
- Упростил бы названия: `getByCurrencyCode` -> `getByCode`, `updateExchangeRate` -> `update`.
- Видимо сервис `AbstractCurrencyLookupService` был выделен отдельно для легитимного использования в `ExchangeService`,
  но мне кажется это overhead и использовал бы напрямую `CurrencyService`.
  Можно еще поговорить про корректность такого наследования с точки зрения `is a`, ведь `DefaultExchangeRateService`
  никак не является частным случаем `AbstractCurrencyLookupService`.
- Чуть точнее имя локальной переменной `List<CurrencyResponse> responseDto` -> `responseDtos`.
- Выделены бизнес-значения в константы - хорошо.
- Класс расчета курс достаточно хорошо читается - классно.

### package servlet

- Удобный `AbstractApiServlet`, выделил методы и состояния общие для сервлетов.
- Круто, что используешь `composition root` для зависимостей.
- Исключения ловятся отдельно от сервлетов - хорошо.
- Отдельный парсер для каждого случая - заморочился молодец.

### package dto
- Разделены запросы и ответы - супер.
- record для dto - идеально.


### package exception
- Свое древо для кастомных исключений - хорошо.
- Сообщения прямо в конструкторах - правильный подход.


### package mapper
- Выделен интерфейс для мапперов - супер.
- Можно попробовать MapStruct.


### package test
- Написаны интеграционные тесты - наверное в первый раз такое встречаю в третьем, это хорошо.

## Общее
- Коммиты в соответствии с конвенцией - гуд.
- http тесты в проекте круто.
- Можно еще покрасивее оформлять pom.xml.
- С этого проекта уже можно учиться пользоваться `Lombok`.

## Итог
- Очень качественный проект, критических замечаний не подметил, можно смело переходить к следующему проекту, удачи!
