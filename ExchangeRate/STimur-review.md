## По коду

#### package model

- Концептуально для `id` лучше подходит `Long` вместо `int` или `Integer`.
- Сейчас модель используется одновременно как Entity и как DTO - нарушение SRP. Рекомендую разделить: модель предметной
  области для DAO слоя, а DTO - для передачи данных между сервисом и контроллером.
- Тот же класс Conversion чистый DTO.
- BigDecimal отличный выбор типа.

#### package dao

- Стандартный стиль большинства Java-проектов - публичные методы стоят сверху, приватные снизу. Таким образом, когда
  кто-то открывает класс, он сразу видит публичный API, а детали реализации скрыты ниже.
- В целом отличный слой.

#### package service

- Нарушение инкапсуляции зависимости:

```java
public class CurrencyService {

    CurrencyDao currencyDAO;
```

- Хорошей практикой является возвращать из сервиса DTO, тем самым скрывая внутреннее устройство модели от контроллера и
  сохраняя границы слоев.
- Сервис не должен напрямую использовать DAO другого сервиса, если уже есть существующий сервис, который инкапсулирует
  работу с этим DAO. Вместо `CurrencyDao` в `ExchangeRateService` стоит использовать `CurrencyService`.

#### package controller

- Зависимости не стоит создавать через `new` прямо в сервлетах. Рекомендую реализовать паттерн Composition Root,
  например через `AppInitializer implements ServletContextListener`, который создаст все зависимости и положит их в
  `ServletContext`. Я вообще удивлен, что у тебя оно работает, обычно создают через `init()`, где их создают либо
  получают через контейнер.
- Таки напрашивается вынести валидацию в отдельный класс:

```java
        if (code == null || code.isBlank() || name == null || name.isBlank()
                || sign == null || sign.isBlank() || sign.length() > 3) {
            resp.setStatus(HttpServletResponse.SC_BAD_REQUEST);
            mapper.writeValue(resp.getWriter(), new ErrorResponse("Отсутствует нужное поле формы"));
            return;
        }
```
- Как уже ранее упоминал, в контроллере обычно предполагается работа с DTO объектами.

#### package utility

- Все утилитарные классы должны иметь модификатор `final` и приватный конструктор.
